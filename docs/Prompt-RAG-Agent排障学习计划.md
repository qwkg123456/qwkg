# Prompt / RAG / Agent 排障 · 详细学习计划

> 目标：不只会「搭一套 RAG/Agent」，而是见到 Badcase 能 **定位层（Prompt / 检索 / 调用 / 生成）→ 复现 → 改一处 → 用评测集验证**。  
> 适用：有 Java / 业务系统基础；已用过或正在用 Dify；准备手写 Spring AI RAG。  
> 周期：**8 周**（可按每周 8～12 小时执行；忙则可拉成 12 周）。  
> 原则：**先分清链路，再改参数；每次只改一个变量；没有评测集就不算会排障。**

---

## 0. 你要练成的能力

学完应能独立完成：

1. 画清三条链路：纯 Prompt、RAG、Agent（含工具调用）
2. 用一张「故障树」把现象归到正确层级
3. 维护 **30 题评测集 + Badcase 表**
4. 对「召回测试能中、Agent 答不对」给出根因与修复
5. 对「假 citation / 泄思考 / 不调工具 / 读不到上传文件」会分类处理
6. 能用 Dify 对照 + Java 最小复现说明同一问题

---

## 1. 排障总图（每周都要对照）

```text
用户提问
  ├─ A. Prompt 层：指令冲突 / 过长 / 诱导通识 / 未要求拒答
  ├─ B. 检索层：未入库 / 切分差 / embedding / TopK / 混合 / Rerank / 过滤
  ├─ C. 调用层：模型未 tool_call / FC 配置错 / 流式 FC / 工具 0 可用
  ├─ D. 生成层：忽略上下文 / 假引用 / 复读 / 截断 / 温度过高
  └─ E. 投喂层：附件未解析 / 变量空 / 会话污染
```

**口诀：** 先看日志有没有检索/工具 → 再看召回片段好不好 → 最后看 Prompt 与生成。

---

## 2. 必备工件（第 1 周必须建齐）

### 2.1 评测集（至少 30 题）

| 字段 | 说明 |
|------|------|
| id | 题号 |
| question | 用户原话 |
| expect_doc | 应命中的文档/文件名 |
| expect_point | 应包含的要点（数字/条款/结论） |
| must_retrieve | 是否必须检索（是/否） |
| tags | 政策/编码/手册章节/寒暄/上传文件 |

题型建议配比：

- 10 题：库内有明确答案（如手册章节、规则名）
- 10 题：易被通识顶上（医学概念、二线治疗等）
- 5 题：应拒答（库中无、或需本地未上传文件）
- 5 题：寒暄/身份（不应强行检索）

### 2.2 Badcase 表

| 字段 | 说明 |
|------|------|
| date | 日期 |
| question | 问题 |
| symptom | 现象（复读/假引用/Null 工具/胡说） |
| layer | A/B/C/D/E |
| evidence | 日志截图要点（使用工具、召回条数） |
| fix | 改了什么 |
| verified | 复测是否通过 |

### 2.3 环境

- Dify：一个绑好知识库的 Agent +（建议）一个 Chatflow「检索→LLM」
- 可选：Java 最小 RAG（ingest / retrieve / rag-chat）
- 模型：至少一个 **确认有 tool_calls** 的（如 `*-tool`），一个弱模型对照

## 3. 周计划详解

### 第 1 周｜分链路 + 建评测集

**学**

- Prompt / RAG / Agent 三张架构图
- 召回测试 vs Agent 对话的差异
- 阅读自己历史 Badcase（高套文档、手册章节、床位费编码等）

**做**

1. 写出故障树（可打印贴墙）
2. 建 30 题评测表（Excel/飞书均可）
3. 对 10 题只做 **Dify 召回测试**，记录 Top5 是否命中

**验收**

- [ ] 能口述「检索 ≠ 调用」
- [ ] 评测集 30 题齐全
- [ ] 至少 10 题有召回测试结果

**练习题**

- 同问法：召回测试一次、Agent 一次，填 Badcase 表「layer」

---

### 第 2 周｜Prompt 排障（A 层）

**典型症状**

- 泄思考 / `<think>` /「假设知识库返回」
- 未检索却长篇通识
- 声称「无法接入知识库」
- 复读用户关键词
- 无依据却打 `[citation]`

**学与改**

| 问题 | 改法 |
|------|------|
| 提示词过长、内心戏太多 | 压缩为输出铁律 + 拒答规则 |
| 「无结果可用自身知识」 | 改为：无工具返回则短拒，禁止通识顶政策 |
| 「工具取决于环境权限」 | 删除，避免模型自我否决 |
| 要求只回数字仍复读 | 文末硬约束 + 换强模型对照 |

**做**

1. 写两版 System Prompt：`verbose` vs `strict-short`
2. 用同一模型跑评测集中 15 题，对比违规率（泄思考/假引用/未检索作答）
3. 加输出过滤规则笔记：去掉 `</think>` 前内容

**验收**

- [ ] strict 版假 citation 明显下降
- [ ] 整理「Prompt 反模式」清单 ≥ 8 条

**本周只改 Prompt，不改检索参数。**

---

### 第 3 周｜检索排障（B 层）

**典型症状**

- 召回测试也不中
- 命中无关段
- 相关段在 Top20 不在 Top5
- 换说法就不中

**排查清单（按序）**

1. 文档是否在本库、索引是否完成  
2. 分段是否过碎/过长  
3. query 是否该带文件名/同义词  
4. TopK 过小  
5. 混合检索是否打开  
6. Rerank 是否把正确段打下去  
7. 元数据过滤是否过严（如 `kngName` 为空）  
8. Score 阈值是否过高  

**做**

1. 选 10 道「应命中」题，做参数对照实验（每次只改一项）：

| 实验 | 变量 |
|------|------|
| E1 | chunk 大小（如 300 vs 800） |
| E2 | TopK 5 vs 10 |
| E3 | 开/关 Rerank |
| E4 | query 原句 vs 关键词短 query |
| E5 | 混合检索开/关 |

2. 记录命中率变化表

**验收**

- [ ] 10 题召回命中率有数据前后对比
- [ ] 能说明「中了但排太后」该加 Rerank 还是改 query

---

### 第 4 周｜调用排障（C 层）★★ 核心周

**典型症状**

- 日志：`使用工具: Null`
- 正文出现假 `<tool_call>` / 只写「我将检索」
- curl 有 `tool_calls`，Agent 仍不调
- 弱模型不调、强 tool 模型会调

**必做实验**

1. **服务端 FC 探测**（对每个对话模型）：

```bash
# tool_choice=auto，检查响应是否含 tool_calls
# 若报 enable-auto-tool-choice → 服务端未开 FC
```

2. **Dify 凭据对照表**

| 项 | 能调库的模型 | 出问题的模型 |
|----|--------------|--------------|
| 函数调用类型 | 工具调用 / 函数调用？ | 是否一致 |
| 流式函数调用 | 支持？ | 不支持时是否关流式试 |
| 模型名 | 是否 *-tool 部署 | 是否旧部署 |

3. **同题双模型**

- 固定 Prompt、固定知识库  
- A：会 tool 的模型；B：弱量化模型  
- 记录：使用工具字段、是否引用库内片段  

4. **编排对照**

- Agent 自动调工具  
- Chatflow：知识检索 → LLM（强制检索）  
- 同一题对比稳定性  

**验收**

- [ ] 写出《调用失败 10 问自检》
- [ ] 至少 1 次把 Null 修成 `dataset_xxx`（或证明应用 Chatflow 强制检索更稳）
- [ ] 能解释：挂载知识库 ≠ 本轮调用成功

**调用失败 10 问（背下来）**

1. 本轮日志使用工具是什么？  
2. 模型是否支持原生 tool_calls？  
3. 凭据是工具调用还是函数调用？  
4. 流式 FC 是否拖垮？  
5. Agent 是否 auto 且模型选择直接答？  
6. 提示词是否诱导「假设返回」？  
7. 知识库是否对 Agent 可见？  
8. Chatflow 强制检索是否已试？  
9. 同题强模型是否正常？  
10. 是不是把「工具 0/0」误当成没挂库？  

---

### 第 5 周｜生成与引用排障（D 层）

**典型症状**

- 有召回仍通识回答  
- 假 `[citation]` / 假文号 / 假编码  
- 答案与片段矛盾  
- Max Tokens 截断导致只剩分析  

**做**

1. 设计三种生成策略并 A/B：

| 策略 | 规则 |
|------|------|
| S1 | 必须引用编号，无片段禁止引用 |
| S2 | 相关度低于阈值则拒答 |
| S3 | 「只输出最终答案，禁止思考」 |

2. 对「有检索仍胡说」的题：把召回片段和模型输出并排人工打分（有用/忽略/编造）

3. 参数：温度 0.2～0.4；总结类 Max Tokens ≥ 2048

**验收**

- [ ] 假 citation 题归零或接近零（在 must_retrieve 题集上）
- [ ] 写出「生成层验收清单」

---

### 第 6 周｜投喂与多模态边界（E 层）

**典型症状**

- 上传 CSV/PDF，模型说「没收到内容」
- 界面有文件，上下文无正文
- 开了 Vision 仍读不了表格

**学**

- 知识库检索 ≠ 会话附件解析  
- Vision ≠ 文档提取  
- 变量 `kngName` 为空的影响  

**做**

1. 矩阵测试：

| 输入 | Agent | Chatflow+文档提取 |
|------|-------|-------------------|
| 纯文本问库内文档 |  |  |
| 上传 CSV 总结 |  |  |
| 上传图片 |  |  |
| 问未入库本地路径文件 |  |  |

2. 结论写进笔记：何种输入必须走提取节点

**验收**

- [ ] 能说明「看见附件」和「模型读到正文」的区别
- [ ] 给出你场景下的推荐编排（文字走 RAG，文件走提取，图片走 VL）

---

### 第 7 周｜Java 手写最小排障台

**目标：** 用代码复现「分层日志」，巩固排障。

**最小接口**

1. `POST /retrieve` → 只返回 chunk + score（对标召回测试）  
2. `POST /rag/chat` → 先检索再生成，打印 `retrieve_hit`  
3. （可选）`POST /agent/chat` → 工具调用，打印 tool name  

**日志字段（强制打）**

```text
traceId, question, retrieve_count, top_scores, tool_names, refused, citation_count
```

**做**

- 用评测集跑一遍，导出 CSV  
- 与 Dify 结果对比 10 题  

**验收**

- [ ] 任意 Badcase 能从日志判断 layer  
- [ ] README 含「如何根据日志排障」一节  

---

### 第 8 周｜综合演练 + 面试叙事

**综合演练（计时）**

抽 8 个陌生 Badcase（可找同事出题），每个限 20 分钟：

1. 判断 layer  
2. 给出最小复现步骤  
3. 只改一处并复测  

**输出物**

1. 《排障手册》一页纸（故障树 + 10 问 + 常见修复）  
2. 评测集最终命中率/调通率数字  
3. 简历子弹（示例）：

> 负责医保知识库 Agent 排障：建立 30 题评测集；定位「召回可用但 Agent 未调用工具」问题；通过模型 FC 校验、凭据改为工具调用、Chatflow 强制检索，将 must-retrieve 题目工具调用成功率从 X% 提升至 Y%；并落地无召回拒答与假引用治理。

**验收**

- [ ] 8 题演练至少 6 题 layer 判断正确  
- [ ] 能在 3 分钟内讲清一个真实案例

## 5. 速查：现象 → 优先查哪层

| 现象 | 优先 |
|------|------|
| 召回测试不中 | B |
| 召回中、Agent 胡说/通识 | C 或 D |
| 使用工具 Null | C |
| 假 tool_call 文本 | C（非原生 FC） |
| 假 citation | D（+ Prompt A） |
| 泄思考 | A + 模型思考开关 + 过滤 |
| 上传文件说没内容 | E |
| 弱模型复读/乱码感 | D + 换模型 + 缩短 Prompt |
| 强模型正常弱模型不行 | C/D 模型能力，不是库坏了 |
